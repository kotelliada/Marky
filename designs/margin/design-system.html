#Margin design system

Everything Marky's screens are built from: two typefaces, one cobalt accent, hairlines instead of cards, and a set of components with every state they can be in. Each component below is shown in light and dark. The prototype uses these same files, so a change here shows up there.

Source files: tokens.css (all values), components.css (component styles), marky.js (component markup, Markdown renderer, sample notes). Sizes in px map 1:1 to dp on Android and pt on iOS.

Syntax stays in sightPreview keeps heading markers faintly in view. Edit mode tints Markdown syntax in the accent, so the two modes read as one document.
Hairlines, not cardsRows are separated by 1 px borders. Only things that float above the page (menus, dialogs, snackbars) get a shadow.
One accentCobalt marks what is interactive, selected or pinned. Red appears only when something is about to be deleted.
Mono means machineTimestamps, labels, code and raw Markdown use Plex Mono. Anything a person wrote or reads as prose uses Plex Sans.

Type scale

Fourteen styles. Values below are read from the live CSS, so they always match tokens.css. Font sizes are sp on Android.

Color

Cool slate neutrals with a slight blue bias, one cobalt accent, and red reserved for deletion. Light follows the system setting; dark is designed separately, not inverted. Contrast is measured against the surface the token is used on; text tokens meet WCAG AA (4.5:1) in both themes.

Eight-digit hex values carry alpha (last two digits). State layers are painted over whatever surface is underneath, which is why they are translucent.

Spacing, radius, motion

Spacing

A 4 px grid. Screen gutters are 20 on phones and 40 on desktop.

Radius

Small radii keep the hairline look precise. Nothing in Marky is fully rounded.

Elevation

One shadow, for floating elements only. In dark, floating surfaces also step up to --mk-float so they separate from the page.

Motion

Short and functional. Every animation is removed when the system asks for reduced motion.

Sizes

Iconography

Line icons on a 24 px grid, 1.75 px stroke, round caps and joins, drawn at 20 px (16 px inside rows and fields). Icons take their color from the text around them: text-2 at rest, text on hover, accent when on. The pin is the only icon with a filled state.

Components

Every component with every state it can take. Hover exists on desktop only; phones go straight from default to pressed. Focused shows the keyboard focus ring, which matters on desktop and for hardware keyboards on tablets.

Search and title fields

The search field opens the Search screen from the notes list and takes input on the Search screen. The title field edits the note title in place, with no visible box.

Note rows

One row per note: title, time since the last edit, a two-line preview of the text without Markdown syntax, and a pin indicator. Sorted pinned first, then by last edited.

Search results

Same row, with every matched word highlighted in the title and in a snippet taken from around the first match. Title matches come first, then text matches, each group by last edited.

Tooltip and shortcuts

Desktop only. Appears after 500 ms of hover or on keyboard focus, and shows the shortcut when there is one. On macOS, Ctrl reads as ⌘.

App bars and layout

56 high on every screen. The hairline under the bar appears only once content scrolls beneath it. On desktop, a 320 sidebar holds the list or the search results and the note sits in a column at most 680 wide.

Markdown nodes

Every node the preview renders, with its source as it appears in edit mode. Preview follows the page theme; switch the theme at the top to check dark.
